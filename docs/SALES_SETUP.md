# 次元来信 · 密码售卖与发货配置

本文件仅供站点所有者使用，不放在网站公开目录。

## 买家流程

购买 → 收到网站链接与独立解锁码 → 打开网站 → 点击「开始测试」 → 输入解锁码 → 测试。

无需注册或绑定账户。同一码可反复使用、可转发；当前浏览器会记住解锁状态。不同浏览器的历史记录独立。

新密码为 6 位纯数字，可能以 0 开头，始终按字符串保存和发送。优先使用 `codes.txt` 导入库存，避免表格软件把开头的 0 去掉。已经发出的旧长码继续有效，旧订单重发仍返回原码。

网站已上线到 https://anima.wayella.com ，真实小红书订单和自动消息尚未接入。网站无法仅凭一个前端付款提示确认订单；发货服务必须先从销售渠道核验付款。

## 方式一：提前生成密码库存

如果所选店铺功能或发货工具支持导入「一行一份卡密」，可先批量生成：

```bash
node scripts/codes.mjs --count 100 --site https://你的正式域名
```

1. 将这批的 `import.sql` 导入正式 D1 数据库。
2. 按发货工具要求导入 `codes.txt` 或 `delivery.txt`。
3. 配置每个已付款订单发一条库存内容，并先用测试订单核对实际收到的内容。

本机生成会避开历史批次与本地数据库。若正式数据库已有的码与离线库存冲突，导入会报唯一键错误，不会覆盖原码；不要交付失败批次，重新生成并确认导入成功。线上订单发码直接在同一数据库内检查并自动重试冲突。

发货工具按订单消耗库存条目，避免把同一条重复卖给不同订单；买家收到的码在网站上可以重复使用，两者互不冲突。

工具支持何种商品、库存格式及自动发送方式，需在实际店铺或工具中确认。本项目不会自动登录店铺，也不会将生成文件自动上传到销售平台。

## 方式二：付款后按订单生成

有服务端 API 接入能力的发货工具可使用：

```text
POST https://你的正式域名/api/fulfillment/issue
Authorization: Bearer 服务器发码认证密钥
Content-Type: application/json
```

请求示例：

```json
{
  "orderId": "ORDER-20261102-0001",
  "productId": "配置的商品ID",
  "paymentStatus": "paid",
  "quantity": 1
}
```

`orderId` 支持 1–128 位字母、数字、下划线、连字符、点与冒号，首位必须是字母或数字。当前接口一次处理一单一份商品；多件数量返回 400，避免少发。

首次调用返回 201：

```json
{
  "orderId": "ORDER-20261102-0001",
  "code": "038271",
  "created": true
}
```

重复或并发通知同一订单会返回原来的码，重复响应为 200、`created: false`。已停用码的订单返回 409，不会另外生成新码。暂时失败返回 500，可保留同一订单号重试。

发货工具收到成功响应后，再通过渠道支持的发货方式，将固定网站链接和返回的 `code` 发给买家。**此接口负责生成与返回解锁码，不负责收款或发送小红书私信。** 不要把服务器认证密钥放进浏览器、公开网页或买家收到的消息。

`paymentStatus` 是受信任发货服务提交的已核验状态，不是网站对平台付款的独立验证。不能让买家自行构造该请求。平台原始回调的验签、商品核验和付款确认需要在对应适配层完成。

## 服务器配置

未完整配置以下内容时，发码接口返回 404：

| 配置名 | 用途 |
| --- | --- |
| `FULFILLMENT_API_KEY` | 至少 32 字符的随机认证密钥，仅交给受信任的发货服务 |
| `FULFILLMENT_ENCRYPTION_KEY` | 64 位十六进制 AES-256 密钥，用于保存和重发订单的原码 |
| `FULFILLMENT_PRODUCT_ID` | 实际出售此测试的商品标识，与请求严格一致 |
| `FULFILLMENT_SOURCE` | 渠道标识，例如 `rednote-store`；默认 `store` |

在 Cloudflare 使用交互式命令保存密钥：

```bash
npx wrangler secret put FULFILLMENT_API_KEY
npx wrangler secret put FULFILLMENT_ENCRYPTION_KEY
```

商品和渠道标识可放入 `wrangler.jsonc` 的 `vars`，然后部署。认证密钥可与发货工具同步轮换；加密密钥必须备份，不能直接替换，否则无法解密旧订单的码。变更商品或渠道标识也会影响订单去重范围。

## 停用与售后

停用一个码需要将其 `activation_codes.disabled` 设为 1。已有浏览器会话也会在下一次 API 请求时失效。当前没有自动退款回调或商家管理页面；需要先由所有者核对订单，再在受控数据库中处理。

重发密码时，按同一订单号再次调用发码接口即可取得原码。密码库存方式则从所有者保存的发货清单或平台发货记录中查找。

首次配置完成后，应实际验证一笔付款与发货：买家收到正确链接和解锁码，码能进入测试，重复通知不会生成第二个码。当前所有验证均为本地与模拟订单，不代表真实店铺已接通。
